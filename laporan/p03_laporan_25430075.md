1. Tujuan Praktikum 
- Memahami dan mampu menerapkan perancangan Entity Relationship Diagram (ERD) fisik basis data relasional.
- Mampu mendefinisikan entitas, atribut, tipe data, Primary Key (PK), Foreign Key (FK), serta constraint (seperti NOT NULL, UNIQUE, ENUM, CHECK, dan AUTO_INCREMENT) menggunakan perangkat pemodelan (Draw.io / phpMyAdmin Designer).
- Mampu merancang relasi antar tabel secara akurat untuk studi kasus Sistem Informasi Akademik (SIAKAD) UM Metro (`akad_075`).

2. Ringkasan Teori
- ERD Fisik (Physical ERD): Representasi rancangan basis data yang sudah disesuaikan dengan sistem manajemen basis data (DBMS) tertentu (seperti MySQL/MariaDB), lengkap dengan spesifikasi tipe data, panjang karakter, serta batasan (constraint) setiap kolom.
- Atribut & Tipe Data Utama:
1. INT, SMALLINT: Untuk data numerik/bilangan bulat (misal: ID jadwal, kapasitas ruangan, SKS, semester).
2. CHAR, VARCHAR: Untuk data teks dengan panjang tetap atau dinamis (misal: NIM, NIDN, nama mahasiswa, kode MK, hari).
3. YEAR: Untuk pencatatan tahun akademik atau angkatan mahasiswa (misal: year(4)).
4. TIME: Untuk pencatatan waktu mulai dan selesai jam perkuliahan.
5. ENUM: Untuk membatasi pilihan nilai tertentu pada kolom (misal: status mahasiswa aktif/cuti/lulus).
- Constraint (Batasan): Aturan integritas data seperti PRIMARY KEY (unik dan pengenal utama), FOREIGN KEY (penghubung antar tabel), UNIQUE (nilai tidak boleh duplikat), dan NOT NULL (wajib diisi).

4. Titik Analisis
- Mengapa tabel perantara seperti jadwal_kuliah dan krs sangat penting dalam perancangan basis data akademik? Tabel perantara digunakan untuk menangani relasi Many-to-Many (Banyak ke Banyak) antar entitas (seperti mahasiswa dengan mata kuliah pada KRS, atau dosen, ruangan, dan mata kuliah pada jadwal) agar terpecah menjadi relasi One-to-Many yang ternormalisasi.
- Apa fungsi dari penggunaan mesin InnoDB pada pembuatan tabel basis data? Untuk mendukung transaksi basis data yang aman serta mengaktifkan fitur integritas referensial Foreign Key beserta aksi ON DELETE CASCADE / ON UPDATE CASCADE.
- Mengapa atribut kunci tamu (Foreign Key) harus memiliki tipe data yang persis sama dengan atribut Primary Key acuannya? Agar mesin database dapat mencocokkan nilai data secara presisi tanpa terjadi error ketidaksesuaian tipe data (*type mismatch*).

5. Hasil Latihan
Melakukan pemetaan struktur tabel dari studi kasus SIAKAD UM Metro ke dalam bentuk skema relasional, di mana setiap tabel memiliki atribut kunci utama (PK) dan kunci tamu (FK) yang saling terhubung secara konsisten:
- Tabel mahasiswa: Menyimpan data identitas mahasiswa (nim, nama_mahasiswa, prodi_mahasiswa, angkatan_mahasiswa, status_mahasiswa).
- Tabel dosen: Menyimpan data pengajar (nidn, nama_dosen, prodi_dosen, email_dosen).
- Tabel mata_kuliah: Menyimpan daftar mata kuliah (kode_mk, nama_mk, sks, semester).
- Tabel ruangan: Menyimpan data ruang kelas (id_ruangan, nama_ruangan, kapasitas).
- Tabel jadwal_kuliah: Mengatur jadwal pertemuan mengajar (id_jadwal, kode_mk, nidn, id_ruangan, hari, jam_mulai, jam_selesai).
- Tabel krs: Mencatat rencana studi mahasiswa (id_krs, nim, kode_mk, tahun_akademik).
